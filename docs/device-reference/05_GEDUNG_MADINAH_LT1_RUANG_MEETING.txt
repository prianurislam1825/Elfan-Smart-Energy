Kipas Ruang Meeting merupakan perangkat kipas angin DIY yang dikendalikan menggunakan Universal IR Remote melalui ekosistem Tuya.

Pengendalian kipas menggunakan sinyal infrared yang telah dilatih (IR Learning) dari remote kipas asli.

Dalam aplikasi Smart Life, terdapat dua profil perangkat IR dengan fungsi yang sama-sama berkaitan dengan kipas. Namun, untuk aplikasi ELFAN, kedua profil tersebut harus digabungkan menjadi **satu perangkat logis**.

Penggabungan dilakukan pada lapisan aplikasi ELFAN, bukan dengan mengubah atau menggabungkan perangkat di Tuya.

### Konsep utama

- Satu perangkat kipas pada dashboard ELFAN.
- Dua profil IR sebagai sumber perintah.
- Kontrol ON dan OFF dipisahkan menjadi dua aksi.
- Speed dan Swing tersedia sebagai kontrol tersendiri.
- Aksi Hidupkan Kipas menjalankan rangkaian Power ON, Speed, dan Swing.
- Aksi Matikan Kipas hanya menjalankan Power OFF.

## 3. Standard Instruction Set

Kedua profil memiliki enam kode perintah berikut.

| Code | Type | Fungsi |
|---|---|---|
| `NegativeIon` | STRING | Kontrol fitur ion negatif |
| `PowerOff` | STRING | Perintah mematikan kipas |
| `PowerOn` | STRING | Perintah menghidupkan kipas |
| `Speed` | STRING | Mengatur kecepatan kipas |
| `Swing` | STRING | Mengatur ayunan kipas |
| `Timing` | STRING | Kontrol timer kipas |

Seluruh kode menggunakan tipe data STRING dengan nilai sesuai nama kodenya.

## 4. Standard Status Set

**Status: Not Data Found**

Tidak tersedia Standard Status Set pada kedua profil IR.

Implikasi:
- Tidak ada data status kipas yang dapat dijadikan sumber konfirmasi langsung melalui Standard Status Set.
- Aplikasi tidak dapat mengandalkan status aktual kipas dari daftar status tersebut.
- Status ON/OFF yang ditampilkan ELFAN harus dikelola secara internal.
- Status internal harus dibedakan dari status fisik perangkat.

## 5. Rancangan Antarmuka ELFAN

### 5.1 Prinsip Antarmuka

Berbeda dengan Smart Life yang menampilkan dua profil IR secara terpisah, ELFAN harus menampilkan satu perangkat kipas.

**Nama perangkat:** Kipas Ruang Meeting

**Lokasi:** Lantai 1, Gedung Madinah.

Kontrol utama yang tersedia:

1. Hidupkan Kipas.
2. Matikan Kipas.
3. Kecepatan.
4. Swing.

Kontrol tambahan dapat dikembangkan kemudian sesuai kebutuhan.

### 5.2 Struktur Menu

| Menu | Fungsi |
|---|---|
| Hidupkan Kipas | Menjalankan rangkaian PowerOn, Speed, dan Swing |
| Matikan Kipas | Menjalankan PowerOff |
| Kecepatan | Mengirim perintah Speed |
| Swing | Mengirim perintah Swing |

Menu ON dan OFF harus terpisah di dalam satu halaman perangkat, bukan dibuat menjadi dua perangkat berbeda.

## 6. Logika Pengendalian ELFAN

### 6.1 Skenario Hidupkan Kipas

Ketika pengguna memilih perintah Hidupkan Kipas, ELFAN menjalankan tiga perintah secara berurutan.

| Urutan | Perintah | Profil IR |
|---|---|---|
| 1 | `PowerOn` | Profil IR Utama |
| 2 | `Speed` | Profil IR Utama |
| 3 | `Swing` | Profil IR Utama |

Alur:

`Hidupkan Kipas → PowerOn → Speed → Swing`

Catatan:
- Perintah harus dijalankan secara berurutan.
- Jeda antarperintah harus dapat dikonfigurasi setelah pengujian IR.
- Nilai kecepatan awal dan kondisi Swing perlu ditentukan pada tahap konfigurasi.
- Jangan mengirim perintah secara paralel karena berpotensi mengganggu urutan penerimaan sinyal IR.

### 6.2 Skenario Matikan Kipas

Ketika pengguna memilih Matikan Kipas, ELFAN hanya menjalankan satu perintah.

| Urutan | Perintah | Profil IR |
|---|---|---|
| 1 | `PowerOff` | Profil IR Kedua |

Alur:

`Matikan Kipas → PowerOff`

Tidak perlu menjalankan perintah Speed atau Swing.

### 6.3 Pengaturan Kecepatan

Pengguna dapat mengakses kontrol kecepatan secara terpisah.

Perintah:

`Speed`

Sumber perintah: Profil IR Utama.

Catatan: Jumlah tingkat kecepatan dan perilaku setiap pengiriman perintah belum ditentukan dalam data perangkat. Hal tersebut perlu disesuaikan dengan hasil pelatihan dan pengujian remote asli.

### 6.4 Pengaturan Swing

Pengguna dapat mengaktifkan atau mengubah ayunan kipas melalui kontrol tersendiri.

Perintah:

`Swing`

Sumber perintah: Profil IR Utama.

Catatan: Perilaku tombol Swing perlu diuji untuk mengetahui apakah setiap pengiriman perintah mengaktifkan, menonaktifkan, atau mengganti mode ayunan.

## 7. Arsitektur Integrasi

ELFAN harus memisahkan identitas perangkat logis dengan identitas profil IR Tuya.

Alur komunikasi:

`ELFAN Mobile → ELFAN Backend → Device Controller → Tuya Cloud API → Universal IR Remote → Kipas`

Struktur logis:

- Satu perangkat logis: `fan_meeting_room`.
- Profil IR utama: `a3a8b3c92366d8cccdlv8x`.
- Profil IR OFF: `a3d520419883fac0c9rthm`.

Kedua profil harus terhubung pada satu konfigurasi perangkat logis agar aplikasi tidak menampilkan dua kipas.

## 9. Pengelolaan Status Perangkat

Karena tidak tersedia Standard Status Set, backend perlu memiliki status internal.

Contoh status:

| Status | Keterangan |
|---|---|
| `unknown` | Status kipas belum diketahui |
| `on` | Perintah ON berhasil dikirim |
| `off` | Perintah OFF berhasil dikirim |
| `processing` | Rangkaian perintah sedang berjalan |
| `error` | Pengiriman perintah mengalami kegagalan |

Ketentuan:
1. Status awal setelah aplikasi atau backend aktif adalah `unknown`, kecuali terdapat status tersimpan yang masih valid.
2. Status berubah menjadi `processing` saat rangkaian perintah dijalankan.
3. Status internal diperbarui setelah pengiriman perintah berhasil.
4. Jika pengiriman gagal, tampilkan status `error`.
5. Jangan menganggap respons sukses API sebagai bukti kipas benar-benar menyala atau mati.
6. Jika kipas dikendalikan melalui remote fisik, status internal ELFAN dapat berbeda dari kondisi sebenarnya.

## 10. Ketentuan Keamanan dan Keandalan

- Hindari menjalankan dua rangkaian perintah kipas secara bersamaan.
- Gunakan antrean perintah atau mekanisme locking.
- Berikan jeda yang dapat dikonfigurasi antarperintah IR.
- Hindari pengiriman ulang otomatis untuk perintah toggle tanpa mengetahui kondisi kipas.
- Sediakan penanganan kegagalan pengiriman perintah.
- Catat riwayat perintah untuk kebutuhan debugging.
- Jangan menyimpan kredensial Tuya langsung di konfigurasi perangkat.

## 11. Skenario Pengujian

| No. | Pengujian | Hasil yang Diharapkan |
|---|---|---|
| 1 | Hidupkan kipas dari ELFAN | Kipas menerima PowerOn, Speed, Swing secara berurutan |
| 2 | Matikan kipas dari ELFAN | Kipas menerima PowerOff |
| 3 | Atur kecepatan | Perintah Speed diterima |
| 4 | Aktifkan Swing | Perintah Swing diterima |
| 5 | Pengiriman perintah gagal | ELFAN menampilkan status error |
| 6 | Perintah dijalankan berulang | Tidak terjadi tumpang tindih proses |
| 7 | Kipas dikendalikan dari remote fisik | Status internal tidak dianggap sebagai status aktual |
| 8 | Backend dimulai ulang | Status perangkat tidak langsung diasumsikan ON atau OFF |

## 12. Batasan dan Pengembangan Lanjutan

Fitur berikut belum dapat dianggap tersedia sebelum dilakukan pengujian:

- Penentuan tingkat kecepatan kipas.
- Pengaturan mode Swing.
- Penggunaan NegativeIon.
- Pengaturan Timing.
- Konfirmasi kondisi aktual kipas.
- Sinkronisasi kondisi kipas setelah dikendalikan melalui remote fisik.

Fitur tambahan dapat dikembangkan tanpa mengubah konsep satu perangkat logis.

## 13. Kesimpulan

Kipas Ruang Meeting menggunakan dua profil IR Tuya yang digabungkan menjadi satu perangkat logis di ELFAN.

Rancangan final:

- **Satu perangkat:** Kipas Ruang Meeting.
- **Dua profil IR:** Profil operasional dan profil Power OFF.
- **Satu tampilan kontrol:** Semua fungsi kipas berada dalam satu halaman.
- **Empat kontrol utama:** Hidupkan, Matikan, Kecepatan, dan Swing.
- **Skenario ON:** PowerOn → Speed → Swing.
- **Skenario OFF:** PowerOff.

Dokumentasi ini menjadi acuan untuk pengembangan database perangkat, backend Device Controller, integrasi Tuya Cloud API, dan antarmuka ELFAN Mobile.
