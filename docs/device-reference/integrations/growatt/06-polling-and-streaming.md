Artinya:| Mode | Karena | Interval yang berlaku ||---|---|---|| `simulate` | Konfigurasi `pollIntervalMs` | `pollIntervalMs`, default `5000` || `growatt` | Minimal 30 detik | `max(pollIntervalMs, 30000)` |> 💡 `30s` adalah batasan / proteksi anti-rate-limit Growatt. Backend ELFAN tidak boleh menurunkan batas ini secara bebas jika menggunakan environment growatt.---## 2. TimeoutImplementasi `server.cjs`:```js

Cara menghandle banyak inverter`server.cjs` menggunakan `Promise.allSettled` per bulatan poll:```js
const results = await Promise.allSettled(sns.map(async (sn) => {if (MODE === "growatt") return fetchGrowattLastData(sn);await new Promise((r) => setTimeout(r, 5));return simulateDevice(sn, Date.now());}));```
Kelebihan:- Satu inverter gagal tidak menghentikan yang lain.- Pendekatan pararel yang sederhana.Keterbatasan:- Jika banyak inverter, jumlah request pararel bisa besar.- Untuk mencegah rate limit, batasi `concurrency` dan tambahkan backoff.Rekomendasi backend ELFAN:1. Batasi concurrency, contoh maximum 5–10 inverter sekaligus.2. Gunakan jeda antar chunk.3. Simpan `nextAttemptAt` untuk retry.4. Gunakan batch `invs_data` jika memungkinkan.---## 4. SSE (Server-Sent Events)Implementasi `api/stream.js`:- Status HTTP `200`.- Header:  ```http  Content-Type: text/event-stream  Cache-Control: no-cache, no-transform  Connection: keep-alive  Access-Control-Allow-Origin: *  ```- Kirim snapshot pertama.- Ulangi setiap 2500 ms.- Hentikan setelah 3 iterasi (7 detik).Serveur `server.cjs`:- `broadcast()` mengirim snapshot ke semua klien SSE.- Ping interval 15 detik.### SinkronisasiKlien SSE mendapat snapshot melalui:```text
data: { ...snapshot... }```
Klien tuple:1. Dapat instance dari `/api/stream` kapan saja.2. Tetap menggunakan polling dari `/api/snapshot` sebagai fallback.3. Update UI ke `buildSnapshot()`.Keterbukaan:- SSE adalah unidirectional (server → client).- Klien tetap bisa memastikan data terbaru melalui `/api/snapshot`.- `lastPollAtMs`, `pollCount`, `mode`, `lastPollOk`, `lastError` membantu mendeteksi keadaan server.---## 5. Perbedaan implementasi local server vs serverless/VercelDari `api/stream.js` dan `api/snapshot.js`:| Aspek | Local server (`server.cjs`) | Serverless/Vercel (`api/snapshot.js` + `api/stream.js`) ||---|---|---|| Stateless / state | Mempertahankan state in-memory | State cocok di memory cache; hit terpisah || Posting | `broadcast()` to connected SSE | Channel bersama, buka/setutup per connection || Timeout | Tidak ada hard limit per connection | `setInterval` batasi 3 iterasi × 2.5s = 7.5s || Cache | Tidak ada cache global pada snapshot | Cache TTL: growatt 25s, simulate 2s || Pengaturan interval | `EFFECTIVE_POLL_MS` | 25s (growatt) / 2s (simulate) || Cache heartbeat | Polling `pollCycle()` secara teratur | Handler `buildSnapshot()` |### Implikasi penting1. Di serverless, setiap request ke `/api/snapshot` atau `/api/stream` dapat menjadi invocation terpisah.2. Snapshot cenderung kurang sereal dengan polling hangat.3. `serverTime` dan `lastPollAtMs` menjadi indikator utama.4. Stream lambda 7 detik mengikuti henti 10 detik Vercel hobby, jadi disesuaikan.---## 6. Mekanisme reconnect- Client dashboard cenderung on `eventSource` bawaan browser.- Server mengirim `data: snapshot`.- Sinkronisasi klien dengan `/api/snapshot` sebagai fallback.Contoh perilaku klien:1.
