# Integration Architecture — Growatt → Backend ELFAN> **Tujuan:** menggambarkan komponen dan alur integrasi, bukan implementasi backend.> **Label:** Konsep arsitektur `BERDASARKAN KONSEP TASK`. Berdasarkan requirement task, repository monitoing-inverter, documentation Growatt, dan isu pola.---## 1. Diagram alur```text
Growatt OpenAPI│  HTTP/JSON: GET /device/inverter/last_new_data, POST /device/inverter/invs_data▼Growatt Integration Service│  Validasi: error_code === 0, timeout, retry, token▼Device Discovery│  GET /plant/list, GET /device/list, GET /device/datalogger/list▼Inverter Poller│  Batch / parallel per device, simpan data▼Data Normalization│  Field mapping, unit, timestamp, status embedding▼Data Repository│  Persist: device catalog, snapshot, raw response, history (jika tersedia)▼ELFAN Energy API│  API read-only untuk frontend/mobile▼ELFAN Mobile│  Tampilan konsumsi, forecast, alarm, history```
---## 2. Tanggung jawab setiap komponen### 2.1 Growatt OpenAPISumber data perangkat:- Data inverter real-time.- Katalog plant, datalogger, inverter.- Alarm dan pertama data historis.Housing:-ikuti endpoint sesuai environment.- Respon konsisten, validasi `error_code`.- JWT/other authentication if relevant.---### 2.2 Growatt Integration ServiceLapisan klien antara ELFAN dan Growatt.Tanggung jawab:- API request ke Growatt.- Token management/env variable.- Timeout, retry, circuit breaker.- Parsing response, validasi `error_code`.- Payload normalization saat keluar.Contoh interface internal yang disarankan:```text
GET /devicesGET /devices/{device_sn}GET /devices/{device_sn}/dataGET /plantsGET /dataloggers```
---### 2.3 Device DiscoveryTanggung jawab:- Dapatkan list plant.- Dapatkan list datalogger/kolektor.- Dapatkan list device / inverter.- Identifikasi `device_sn`.- Relasi `device_sn` ↔ `datalogger_sn`.- Update device catalog saat device rusak.---### 2.4 Inverter PollerTanggung jawab:- Polling data real-time secara berulang.- Mendukung batch `invs_data`.- Mengelola concurrency dan rate limit.- Mengekspor status `online/offline`.- Menghemat history local (opsional).---### 2.5 Data NormalizationTanggung jawab:- Ubah field Growatt ke schema ELFAN.- Ubah unit, format timestamp, status enum.- Tamahkan device metadata:  - `device_sn`  - `datalogger_sn`  - `plant_id`  - `source`  - `poll_at`  - `error_code`  - `http_status`- Bersihkan field yang tidak valid.---### 2.6 Data RepositoryTanggung jawab:- Menyimpan asset/daftar device.- Menyimpan status/instrument data monitoring.Domain:- Data plant.- Data datalogger.- Data inverter.- Data monitoring real-time.- Data historis.---### 2.7 ELFAN Energy APIAPI read-only yang disajikan ke frontend/mobile.Layout utama:- `/devices`- `/devices/{device_sn}`- `/plants`- `/monitoring`- `/alarms`- `/history`---### 2.8 ELFAN MobileKlien konsumsi:- Tampilan meteran, grafik, alarm.- Pembaruan real-time.- History per device atau per plant.- Notifikasi error dan offline.---## 3. Rencana pemisahan data### 3.1 Data plantSumber:- `GET /plant/list`- `GET /plant/details`- `GET /plant/data`Data:- `plant_id`- `name`- `user_id`- `status`- `capacity` (jika tersedia)- `timezone`---### 3.2 Data dataloggerSumber:- `GET /device/datalogger/list`- `GET /device/datalogger/validate`- `GET /device/list` (field `datalogger_sn`)Data:- `datalogger_sn`- `plant_id`- `type`- `manufacturer`- `model`- `last_update_time`- `status`---### 3.3 Data inverterSumber:- `GET /device/inverter/last_new_data`- `POST /device/inverter/invs_data`Data:- `device_sn`- `dataloggerSn`- `status`- `statusText`- `pac`- `ppv`- `vacr`- `vpv1`, `vpv2`- `ipv1`, `ipv2`- `fac`- `pf`- `temperature`- `powerToday`- `powerTotal`- `faultCode`- `warnCode`- `time`- `realOPPercent`- `timeTotal`---### 3.4 Data monitoringSumber:- `last_new_data`- `invs_data`- history simulator jika diperlukan, tetapi harus label benar.Data:- `device_sn`- `plant_id`- `datalogger_sn`- `poll_at`- `snapshot`- `history`- `online`- `source`---### 3.5 Data historisYang tersedia di repo:- History **simulasi** (local). Jangan dimasukkan ke data aktual.- Kinerja Growatt: belum diverifikasi.Kesimpulan:- Batasi historis Growatt ke data yang benar berasal dari Growatt `data/historic`, `inv_data_info`, `storage_data`, `inverter/data`, dan lainnya (jika konfirmasi lingkungan valid).- API historis belum diverifikasi dalam kode yang diamati.---## 4. Contoh alur gRPC/HTTP internal ELFAN```text
Mobile/Frontend│  GET /energy/growatt/devices▼ELFAN Energy API│  GET /growatt/devices▼Growatt Integration Service│  GET /growatt/device-discovery▼Device Discovery│  GET /plant/list, GET /device/list, GET /device/datalogger/list▼Metadata│  Persist▼Inverter Poller (batch / parallel)│  POST /device/inverter/invs_data▼Data Normalization│  Map to ELFAN schema▼Data Repository│  Insert/upsert▼ELFAN Energy API└─ GET /energy/growatt/devices/{device_sn}▼ELFAN Mobile```
