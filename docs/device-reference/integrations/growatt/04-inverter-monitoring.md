Alur pollingImplementasi `server.cjs`:```js
EFFECTIVE_POLL_MS =MODE === "growatt" ? Math.max(POLL_INTERVAL_MS, 30000) : POLL_INTERVAL_MS```
Artinya:- Mode `simulate`: interval dari konfigurasi, default `5000 ms`.- Mode `growatt`:  - Interval minimum `30000 ms` (30 detik), walaupun `pollIntervalMs` lebih kecil.  - Timeout request `REQUEST_TIMEOUT_MS`, default `10000 ms`.Vehicle polling:```js
const sns = Array.from(state.devices.keys());const results = await Promise.allSettled(sns.map(async (sn) => {if (MODE === "growatt") return fetchGrowattLastData(sn);await new Promise((r) => setTimeout(r, 5));return simulateDevice(sn, Date.now());}));```
Pola:1. Ambil daftar device.2. Lakukan request per device dalam 1 batch `Promise.allSettled`.3. Jika `fetch` berhasil dan `error_code === 0`, simpan data.4. Jika gagal, jangan hancurkan device lain.5. Setiap 12 poll, print ringkasan.6. Broadcast snapshot via SSE.---## 4. Kelebihan dan keterbatasan setiap metode### `GET /device/inverter/last_new_data`**Kelebihan:**- Sederhana, 1 request per inverter.- Cocok untuk mitigasi latency rendah.- Mengembalikan `dataloggerSn` dan `statusText`.**Keterbatasan:**- 1 request per inverter; cepat memakan quota API jika banyak inverter.- Cepat kena rate limit jika cadence tinggi.- Belum tentu mencakup historis.### `POST /device/inverter/invs_data`**Kelebihan:**- Batch, mengurangi jumlah request.- Cocok jika banyak inverter.**Keterbatasan:**- Struktur response dalam contoh cukup kaku (keyed by device SN).- Perilaku batch error belum diuji dalam implementasi yang diamati.- Interface endpoint growatt bisa berbeda antar environment.### Simulasi localImplementasi mendukung simulasi tanpa menghubungi Growatt:- `server.cjs` menggunakan mode `simulate`.- Data simulasi bersifat **fiktif**:  - kurva daya berdasarkan waktu virtual,  - fault acak,  - `dataloggerSn` disimulasikan `SIM-DL-`.- Data simulasi **jangan** dibaca sebagai data riil.---## 7. Hubungan caching snapshot`api/snapshot.js` menggunakan mekanisme caching:```js
const cacheTtlMs = mode === "growatt" ? 25000 : 2000;```
Artinya:- Mode growatt: snapshot di-cache selama 25s.- Mode simulate: snapshot di-cache selama 2s.Side effect:- Ditolak penggunaan data stream lebih cepat dari cache.- Fungsi umum dari caching: menghindari kelebihan pollling ke Growatt.> Back End ELFAN harus hati-hati: caching terhadap data Live menyebabkan `server-time` atau `lastPollAtMs` tidak sinkron. Pastikan timestamp terakhir diperbarui pada setiap pemulihan cache.---## 8. Status onlineKode di `server.cjs`:```js
online: !!(raw && Date.now() - state.lastPollAtMs < EFFECTIVE_POLL_MS * 4),```
Artinya:- Device ditandai `online` selama kurang lebih 4x interval polling terakhir.- Jika kurang dari 4x interval, `online = false`.Implementasi ini membantu mendeteksi data stale, tetapi ini adalah **pembacaan dari waktu polling**, bukan status jaringan secara langsung.
